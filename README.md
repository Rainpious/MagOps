# MagOps

面向磁测项目的 Windows 桌面工作台，将工区资料、坐标与空间处理、航线设计、外业记录和成果来源管理放在同一项目中。

MagOps is a Windows desktop workspace for magnetic-survey project organization, spatial data, flight-route planning and traceable survey artifacts.

## 下载与运行

从 [Releases](https://github.com/Rainpious/MagOps/releases) 下载 Windows x64 ZIP，完整解压后运行 `MagOps.exe`。发行包自带 .NET 运行时，无需单独安装；命令行工具位于 `cli/MagOps.Cli.exe`。当前版本为 0.9.58，仍在持续开发和实机验收。

## 报告编写

打开项目和工区后，从「报告编写」维护项目单位、人员、平台和磁探头型号资料，生成 Word 草稿并查看输入来源。平泉式工作稿使用随程序内置的空白模板。塔尔曼式工作稿需选择具备对应内容控件和题注的兼容 .dotx，可按设备台账更新平台、探头、日变基站及站点字段。更新前可核对差异，手工解释与备注随工作稿保存。

## 解决哪些问题

磁测项目的时间往往花在反复画线、拆分数据、核对时间与坐标、查找地形，以及确认“这份成果来自哪批原始数据”上。MagOps 将这些步骤放进同一工作区，减少地图、表格和文件夹之间的反复切换。下面说明具体可做的事情；目前没有统一的节时基准测试，不承诺固定效率提升比例。

### 自动绘制航线、划分子工作区

面对不规则工区，手工设计通常要重复画平行测线、裁切边界、调整方向，再拆成可执行的航线；边界或测线距一变，又需要逐条检查。

MagOps 可以在工区边界基础上配置航线参数，生成航线并在预览图中核对；支持分区绘制与调整、分区状态保存及重开恢复，并导出 KML。重复检查线与独立交叉检查线分别管理，便于区分用途和关联关系。导入的 OVKML、已支持结构的 OVOBJ 踏勘轨迹可作为切割工区时的道路参考。

这样可以把精力放在“分区是否合理、测线方向是否适合现场”上，减少逐条复制测线、重新描边和重开项目后重做分区的操作。起降点推荐与编辑目前已冻结；道路参考也不代表软件已经确认道路可通行或起降位置安全。

### 数据预处理

外业数据往往分散在不同日期、仪器和架次目录中。进入后续处理前，需要找齐资料、检查字段、核对时间，再区分有效作业段和转弯、转场等其他记录；只靠文件名和表格筛选，容易反复返工。

MagOps 提供原始资料扫描与核对、航段和分线候选核验，以及处理用 CSV 输出入口。已有中间 CSV 也可通过明确的坐标字段映射进入空间分线，保留已有数值及处理阶段，避免把已经处理过的数据再次当成原始数据改正。候选归属需要结合预览和人工核验，不能把自动识别直接当作最终测线成果。

配套表格工具支持 CSV/TXT/TSV 合并、表头对齐、线号整理、分组统计和动态噪声计算，减少逐表复制粘贴和重复编写临时公式。具体入口和输入要求以界面提示为准，不是任意仪器格式都能直接导入。

### 日变与地面磁测

日变处理费时的不只是计算，还包括确认测量记录与基站记录是否处在同一时间基准、哪些记录有有效改正依据，以及多次观测应归到哪个测点。

MagOps 可检查已支持的 GSM 原始记录；在明确 session、时间及选择映射后，导出日变试算与点统计，保留原值、时间假设和未改正原因。统计按仪器、session、状态和完整点号区分，提供均值与中位数，便于对照复核。日变质量视图帮助查看相关时间区间及原因，减少从结果逐行反查来源的工作。

这些输出仍属于需要复核的试算资料：软件不会替未知时间补造 UTC，也不把一次导出视为正式验收通过。

### 坐标与地形

边界、测线和外部成果可能采用不同坐标表达；如果每次都手动整理经纬度、确认坐标轴和中央经线，再逐张寻找覆盖工区的地形瓦片，准备工作会被反复打断。

MagOps 集中提供坐标转换、空间文件检查、边界与面积处理，以及共享 GeoTIFF 地形库。AW3D30 下载可按范围检查本地覆盖并补齐缺失瓦片，让多个项目复用同一公共库，减少重复下载和散落的地形副本。

坐标系、时间和高程基准仍需明确确认。AW3D30 是 DSM，不能直接等同于裸地 DTM；地形覆盖也不意味着飞行高度与安全条件已经核验。

### 工区与成果管理

当一个项目包含多个工区、多个处理批次和外部软件输出时，单靠“最终版”“最终版2”等文件名，很难判断成果是否过期、是否属于当前工区，或输入数据是否已改变。

MagOps 将资料登记、工区归属、成果身份和文件变化检查放在项目中管理。外部成果可以整包登记并保留来源声明及文件校验信息，帮助发现缺失或变化，减少逐个文件比对和重新整理交接清单的工作。外部成果登记后仍需审查，不会自动标记为质量通过。

### 保留桌面入口，也提供命令行

桌面界面适合预览和人工核验；CLI 提供项目查询、数据检查、试算、地形下载和成果登记等入口，可用于重复执行已明确参数的步骤。运行 `cli/MagOps.Cli.exe` 查看命令入口。

## 地形设置

在“绘制航线 → 地形库 → AW3D30 下载设置”中设置自己的 JAXA 账号及公共库路径。路径可复制，点击“更改…”选择其他库。“自动下载缺失地形”默认开启，已有手动设置会保留。账号凭据由 Windows 当前用户加密保存在本机，不随项目导出；本仓库及发行包不提供共享账号。

AW3D30 是地表模型（DSM），不等同于裸地 DTM。下载数据需遵守 [JAXA 数据政策](https://earth.jaxa.jp/en/data/policy/) 与来源标注要求；软件 MIT 协议不替代数据许可。

## 当前进度

- 起降点规划已冻结，前端不提供推荐或编辑入口。踏勘轨迹保留为工区切割参考。
- 日变处理等试算结果需要人工核验，不代表正式生产验收；质量提示也不替代飞行安全审查。
- 项目变更预览只生成影响信息，不执行目录删除、迁移等操作。
- OVOBJ 属于厂商格式，兼容性仅覆盖已实现和测试的结构，不保证所有版本。
- 网络下载可能遇到 TLS 或网络故障；离线已入库瓦片可复用。

## 从源码构建

需要 Windows x64 和 .NET 10 SDK（版本见 `global.json`）。

```powershell
dotnet build MagOps.CSharp.sln -c Release
dotnet run --project tests/MagOps.SmokeTests/MagOps.SmokeTests.csproj -c Release
dotnet run --project src/MagOps.Desktop/MagOps.Desktop.csproj -c Release
```

发布自带运行时的桌面程序：

```powershell
dotnet publish src/MagOps.Desktop/MagOps.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o dist/MagOps
```

源码按 `Core`、`Infrastructure`、`Application`、`Reporting`、`Desktop` 和 `Cli` 分层。`tests/MagOps.SmokeTests` 是可独立运行的回归测试入口。公开模板和边界样例使用合成坐标；不包含实际项目资料、内部工作记录及私有验收脚本。
